# 안심지키미 업무 설명 미팅 정리

원문: `workflow_explanation_meeting_audio_transcription.md`  
목적: 안심지키미 운영 업무 흐름을 정리하고, AX Project 관점에서 자동화/개선 가능 영역을 도출한다.

## 1. 핵심 요약

- 안심지키미 운영은 매일 발생하는 위험 대상자 확인, 전화 확인, 주시 처리, 출동 요청 등록, 주간 보고서 작성으로 이어진다.
- 현재 많은 작업이 마스터 페이지, 구글 스프레드시트, 엑셀, 피그마, 카카오톡, 슬랙, 한글 문서 사이를 오가며 수기로 처리된다.
- 마스터 페이지는 당일 데이터 중심으로 동작하며, 과거 일자 데이터 조회와 주간 집계가 불편하다.
- 보고서 작성을 위해 같은 내용을 여러 위치에 반복 입력하거나, 데이터를 다운로드/복사/가공/이미지화/업로드하는 절차가 존재한다.
- 현지 관리자 업무에서는 기기 설치 후 수신 여부 확인을 본사에 요청해야 해서 현장 대기 시간이 발생한다.
- AI/자동화 적용 우선순위는 보고 데이터 통합, 주간 보고 자동 생성, 전화 대상 추천, 기기 수신 확인 간소화로 볼 수 있다.

## 2. 주요 시스템과 채널

### 마스터 페이지

- 내부에서 "안심지키미 마스터 페이지"로 부르는 운영 관리 사이트.
- 위험 관리, 출동 요청 관리, 설정 관리, 대시보드 이미지 업로드 등에 사용된다.
- 현재 일부 계정은 공유 계정 형태로 사용하는 것으로 보인다.
- 당일 위험 데이터 조회는 가능하지만, 어제/그제 등 과거 일자 위험 목록 조회가 제한적인 것으로 설명됐다.

### 구글 스프레드시트

- 위험 확인 결과, 전화 내용, 일별/월별 처리 현황 등을 별도 기록하는 데 사용된다.
- 마스터 페이지에서 보고용 데이터가 충분히 추출되지 않아 보완 장부처럼 운영된다.

### 슬랙

- 위험 리스트 또는 일부 자동화 결과가 공유되는 채널로 언급됐다.
- 기기 변동 사항, 설치/회수 수량 확인 등도 슬랙에 별도 저장/공유되는 것으로 보인다.

### 카카오톡

- 울진/영덕 현지 관리자와의 실시간 소통 채널.
- 설치, 회수, AS, 출동, 기기 위치 변경, 수신 확인 요청 등이 카카오톡으로 오간다.

### 엑셀 / 피그마 / 한글 문서

- 엑셀: 위험 발생 현황 집계, 그래프 생성, 주간 통계 정리.
- 피그마: 그래프 이미지를 보고용 형태로 디자인/이미지화.
- 한글 문서: 부사장 보고용 자료 작성.

## 3. 주요 역할

- 위험 관리 담당자 / 고객센터 외주 인력: 위험 대상자 확인, 그래프 판단, 전화 확인, 주시 처리, 기록 작성.
- 김미정 님 / 경주 님: 위험 관리 및 처리 기록 업무를 주로 수행하는 인물로 언급됨.
- 현지 관리자: 설치, 회수, AS, 실제 현장 출동, 기기 위치 변경 등을 수행.
- 김남섭팀장 / 이경주님: 현지 관리자 카카오톡방에서 소통하는 인물로 언급됨.
- CTO님: 주간 위험 발생 명단 또는 데이터 추출 파일을 제공하는 역할로 언급됨.
- 대표님: 주간 위험 현황 보고를 받는 대상.
- 부사장님: 울진 중심의 별도 주간 보고를 받거나 일부 자료를 직접 다운로드/정리하는 대상으로 언급됨.

## 4. 위험 관리 업무 흐름

### 4.1 위험 발생

- 매일 아침 위험 대상자 목록이 생성된다.
- 회의에서는 오전 8시 15분 기준 위험 리스트가 올라온다고 설명됐다.
- 새벽 3시 이후 움직임이 없거나, 리모컨 사용/움직임이 일정 시간 이상 없는 경우 위험 점수가 낮아지고 위험 대상자로 표시된다.
- 오후에도 한 번 더 위험 발생자가 뜨는 흐름이 있는 것으로 언급됐다.

### 4.2 위험 대상자 확인

담당자는 마스터 페이지에서 대상자를 한 명씩 확인한다.

확인 기준:

- 최근 움직임 그래프
- 리모컨 사용 여부
- 온도/습도/조도 변화
- 최근 연락 이력
- 중복 위험 발생 횟수
- 기존 특이 패턴 여부

판단 예시:

- 온도와 움직임이 함께 떨어지면 집에 없는 경우로 추정할 수 있다.
- 움직임은 있으나 리모컨 사용이 거의 없는 사용자는 TV가 없거나 리모컨을 잘 쓰지 않는 패턴일 수 있다.
- 중복 횟수가 많은 사람은 반복적으로 위험이 떴다가 양호로 돌아온 이력이 있어 즉시 전화하지 않을 수도 있다.
- 처음 위험이 뜬 사람이나 그래프가 평소와 다르면 전화 대상이 될 가능성이 높다.

### 4.3 전화 여부 판단

- 전화 여부는 현재 사람이 그래프와 이력을 보고 판단한다.
- 최근 3주 안에 연락한 사람은 바로 전화하지 않고 주시 처리하는 기준이 언급됐다. 기존에는 2주 기준이었으나 3주로 바뀐 것으로 보인다.
- 전화 대상은 하루 지역별 약 10~15건, 전체 약 20~30건 정도로 언급됐다.
- 전화를 걸어 병원 입원, 외출, 보호자 확인 등 상황을 파악한다.

### 4.4 처리 상태

| 상태 | 의미 |
| --- | --- |
| 양호 | 위험 발생 후 움직임 또는 리모컨 입력이 다시 들어와 자동 정상 전환된 상태 |
| 주시 | 현재 집에 없거나 병원/외출 등으로 위험 알림을 계속 띄우지 않도록 처리한 상태 |
| 위험 | 아직 확인/처리가 필요한 상태 |
| 경고 | 전원 차단, 기기 고장, 데이터 미수신 등으로 데이터가 아예 들어오지 않는 상태 |

주시 처리 특징:

- 병원 입원, 외출, 보호자 앱의 외출 설정 등으로 주시 처리될 수 있다.
- 주시 상태에서도 다시 움직임이나 리모컨 사용 데이터가 들어오면 자동으로 양호 상태로 풀린다.
- 보호자가 앱에서 외출 설정을 하면 마스터 페이지에도 일반 보호자 메시지로 기록되는 것으로 보인다.

## 5. 출동 요청 및 대시보드 카운트 흐름

### 5.1 현장 출동 완료

- 실제 현장 출동뿐 아니라 전화 확인 건도 출동 요청 관리에 등록해 현장 출동 완료 카운트로 집계하는 운영 흐름이 있다.
- 보호자가 앱으로 출동 요청을 하는 경우도 출동 요청 관리에 함께 표시되고 카운트된다.
- 전화한 사람은 원칙적으로 출동 요청 관리에 등록하는 것으로 설명됐다.

### 5.2 전화 확인 / 외출 확인

- 위험 관리 화면에서 보고 유형 또는 주시 설정 사유를 무엇으로 선택하느냐에 따라 대시보드의 전화 확인, 외출 확인 카운트로 반영된다.
- 어떤 사유가 어떤 카운트로 연결되는지 정확한 매핑은 추가 확인이 필요하다.
- 해당 매핑은 과거 기획/설정 변경과 관련되어 있으며, 개발/기획 쪽 확인이 필요하다는 언급이 있었다.

### 5.3 운영상 특이점

- 대시보드에 필요한 카운트를 맞추기 위해 일부 항목을 임의로 출동 요청 관리에 등록하는 흐름이 있다.
- 시스템 구조가 현재 운영 방식과 완전히 맞지 않아 보고용 수치를 만들기 위한 보완 작업이 발생한다.

## 6. 주간 보고 업무 흐름

### 6.1 대표님 보고

주간 보고는 지난주 일요일부터 토요일까지의 자료를 기준으로 작성되는 것으로 설명됐다. 예시로 14일부터 20일까지의 주간 범위가 언급됐다.

주요 포함 내용:

- 지역별 위험 발생/처리 현황
- 현장 출동 완료
- 외출 확인
- 전화 확인
- 기기 변동 사항
- 설치/회수 내역과 회수 사유
- 주간 안심 뉴스 또는 전화 확인 주요 내용

현재 흐름:

1. 마스터 페이지에서 일일 지역별 위험 데이터를 다운로드한다.
2. 매일 데이터를 저장해 일주일치를 취합한다.
3. 구글 스프레드시트에 수기 기록된 전화/위험 처리 내용을 정리한다.
4. 엑셀에 데이터를 넣어 그래프를 만든다.
5. 그래프 이미지를 피그마로 가져가 보고용 이미지로 가공한다.
6. 최종 이미지를 파일로 export한다.
7. 마스터 페이지 설정 관리에서 이미지 파일명을 입력/저장해 대시보드에 표시한다.
8. 대표님에게 주간 보고 자료로 전달한다.

### 6.2 부사장님 보고

- 울진은 별도 주간 보고가 작성되는 것으로 설명됐다.
- CTO가 주간 위험 명단 또는 엑셀 추출 데이터를 제공하고, 이를 기반으로 추가 편집을 수행한다.
- 한글 문서에는 위험 관리 건수, 출동 수, 설치/회수/보호자 변경/AS 출동 등 변동 사항이 들어간다.
- 일부 미설치자 명단 등은 부사장님이 마스터 페이지에서 직접 다운로드하는 흐름으로 바뀐 것으로 보인다.

## 7. 현지 관리자 업무 흐름

### 7.1 현재 방식

- 울진과 영덕 카카오톡방에서 현지 관리자들과 소통한다.
- 현지 관리자는 설치, 회수, AS, 실제 출동, 기기 위치 변경 등을 수행한다.
- 설치 후 기기 데이터가 정상 수신되는지 본사에 확인 요청을 한다.
- 본사 담당자가 마스터 페이지 또는 시스템에서 수신 여부를 확인해 알려준다.

### 7.2 불편 사항

- 현지 관리자가 직접 기기 수신 여부를 확인할 수 없다.
- 설치 현장에서 본사 응답을 기다리며 5분 이상 대기하는 경우가 있다.
- 기기 수신 확인은 단순하지만, 확인 요청과 응답이 카카오톡으로 반복된다.

### 7.3 개선 아이디어

- 현지 관리자용 단순 웹 페이지 제공.
- 시리얼 번호 입력 후 "수신 확인" 버튼을 누르면 마지막 수신 상태를 표시.
- 정상 수신이면 초록색, 미수신이면 빨간색 등으로 단순하게 표시.
- 가능하면 버튼 클릭 후 기기에 즉시 신호 요청 명령을 보내고 몇 초 내 확인.
- URL을 카카오톡방 공지에 고정해 앱 설치 없이 사용.
- 추후 사진 업로드까지 확장 가능하지만, 1차 범위는 수신 확인으로 제한하는 것이 현실적이다.

## 8. 현재 문제점

### 데이터/시스템 문제

- 마스터 페이지에서 과거 위험 데이터 조회가 어렵다.
- 당일 자료 중심이라 주간 보고용 누적 데이터 관리가 불편하다.
- 위험 처리 이력과 전화 확인 내용이 보고용 형태로 바로 추출되지 않는다.
- 출동, 전화 확인, 외출 확인 카운트 산정 기준이 운영자에게 직관적이지 않다.
- DB 또는 화면의 과거 네이밍과 현재 화면 용어가 달라 데이터 해석에 혼선이 있다.

### 업무 문제

- 같은 내용을 마스터 페이지, 구글 시트, 출동 요청 관리, 보고서에 반복 입력한다.
- 주간 보고를 위해 다운로드, 복사, 집계, 그래프 생성, 이미지 편집, 업로드를 반복한다.
- 전화 대상 판단이 담당자 경험에 의존한다.
- 현지 관리자와의 설치/AS 피드백이 카카오톡에 흩어져 있다.
- 현장 기기 수신 확인을 본사 담당자가 대신해야 한다.

### 보고 문제

- 대표님 보고, 부사장님 보고, 대시보드 표시용 데이터가 서로 다른 형식으로 가공된다.
- 보고서가 이미지 기반으로 관리되어 데이터 재사용성이 낮다.
- 일부 자료는 자동화되어 있지 않고 파일명/URL/업로드 경로를 수기로 맞춰야 한다.

## 9. AX 적용 후보

### 9.1 보고 데이터 통합

목표:

- 마스터 페이지 또는 별도 관리 화면에서 전화 확인, 주시 처리, 출동 등록, 보고용 메모를 한 번만 입력하게 한다.

기대 효과:

- 구글 시트 중복 입력 감소
- 주간 보고서 작성 시간 절감
- 처리 이력 조회 가능
- 데이터 누락과 카운트 불일치 감소

### 9.2 주간 보고 자동 생성

목표:

- 일별 위험 데이터와 처리 이력을 자동 집계해 주간 보고 초안을 생성한다.

포함 가능 항목:

- 지역별 위험 발생/처리 건수
- 전화 확인/외출 확인/현장 출동 건수
- 설치/회수/AS/보호자 변경 내역
- 주요 안부 확인 내용 요약
- 대표님 보고용 이미지 또는 PDF
- 부사장님 보고용 한글 문서 초안

적용 방식:

- 1차: 구글 시트 또는 다운로드 엑셀 기반 자동 집계
- 2차: 마스터 페이지/DB 직접 연동
- 3차: 보고 템플릿 자동 생성 및 업로드 자동화

### 9.3 전화 대상 추천

목표:

- 위험 대상자 중 전화 우선순위를 자동 추천한다.

판단 후보 기준:

- 첫 위험 발생 여부
- 최근 3주 내 연락 여부
- 중복 위험 횟수
- 최근 7일 그래프 변화
- 움직임/리모컨 사용 패턴
- 온도/조도/습도 변화
- 과거 주시 처리 사유

주의:

- 자동 판단이 아니라 "추천" 수준으로 시작하는 것이 현실적이다.
- 최종 전화 여부는 운영자가 결정해야 한다.
- 그래프 패턴 기준은 담당자 인터뷰를 통해 더 구체화해야 한다.

### 9.4 현지 관리자용 수신 확인 페이지

목표:

- 현지 관리자가 설치 현장에서 직접 기기 수신 상태를 확인한다.

1차 기능:

- 시리얼 번호 입력
- 수신 확인 버튼
- 정상/미수신 상태 표시
- 마지막 수신 시간 표시

확장 기능:

- 설치 사진 업로드
- 설치 완료 체크
- AS/회수 결과 등록
- 카카오톡 공유용 결과 캡처 또는 링크 생성

### 9.5 카카오톡/슬랙 업무 정리 자동화

목표:

- 현지 관리자 피드백과 내부 공유 내용을 구조화된 업무 기록으로 전환한다.

가능 방식:

- 슬랙 입력을 기준으로 자동 집계
- 카카오톡 내용을 수동 업로드 후 AI가 설치/회수/AS 내역 정리
- 향후 별도 웹 입력 폼으로 전환

## 10. 우선순위 제안

| 우선순위 | 과제 | 이유 |
| --- | --- | --- |
| 1 | 주간 보고용 데이터 통합/집계 | 반복 수작업이 많고 대표/부사장 보고에 직접 영향 |
| 2 | 마스터 페이지 과거 이력 조회 개선 | 당일 데이터만 보는 구조가 주간 관리의 핵심 병목 |
| 3 | 현지 관리자 수신 확인 페이지 | 기능 범위가 작고 현장 대기 시간을 바로 줄일 수 있음 |
| 4 | 전화 대상 추천 | 효과는 크지만 판단 기준 정제가 필요 |
| 5 | 카카오톡/슬랙 정리 자동화 | 채널 구조와 입력 방식 정리가 먼저 필요 |

## 11. 추가 확인 필요 사항

- 마스터 페이지 접근 권한과 테스트 계정 제공 가능 여부
- 위험 발생 알고리즘의 정확한 조건
- 오전/오후 위험 리스트 생성 시간과 기준
- `주시 설정 사유`와 대시보드 카운트 간 매핑
- 출동 요청 관리에 전화 확인을 등록하는 공식 운영 기준
- 구글 스프레드시트의 실제 컬럼 구조
- 대표님 보고서와 부사장님 보고서의 최종 템플릿
- 주간 보고 기준 기간의 확정: 일요일~토요일 기준인지
- DB에서 과거 위험 데이터와 처리 이력이 실제로 저장되는 범위
- 현지 관리자용 수신 확인 기능에 필요한 API/권한
- 기기에 즉시 신호 요청을 보내는 기존 기능의 API 사용 가능 여부

## 13. 용어 정리

| 용어 | 설명 |

| 안심 뉴스 | 전화 확인 내용 등 주간 보고에 들어가는 서술형 주요 내용으로 보임 |
