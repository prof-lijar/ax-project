# Outbound Slack messaging

Nexgent uses Slack's official Python SDK and the Web API
`chat.postMessage` method for outbound messages. This integration has no
Socket Mode, events, mentions, direct-message workflow, conversations, slash
commands, or public webhook endpoint.

## Architecture and safety

`ax_integrations.SlackService` is the single reusable Slack boundary for
agents, workflows, scheduled jobs, and background processes. Those callers
must not import `slack_sdk` directly. The adapter provides:

- async plain-text, thread-reply, and Block Kit delivery;
- a default channel and configured logical destinations;
- rejection of arbitrary or unapproved channel IDs;
- a ten-second configurable timeout and one bounded `Retry-After` retry;
- structured status logs that omit tokens, message text, blocks, metadata,
  and raw provider errors;
- sanitized `SlackMessageResult` values and injected clients for tests.

Only the IDs in `SLACK_DEFAULT_CHANNEL_ID` and `SLACK_CHANNEL_<NAME>` are
approved. Channel IDs generated by a model or supplied at runtime are rejected
unless they equal one of those configured IDs. `SlackMessage.metadata` is
local caller context: it is validated but is not sent to Slack or written to
delivery logs.

Weekly care reports are more sensitive than operational smoke messages. Their
delivery adapter lives in `workflows/weekly_report/slack_delivery.py`, remains
outside the report-generation graph, and requires the explicit
`--approve-sensitive-delivery` operator flag. This avoids duplicate sends from
graph retries and preserves the human-approval boundary. It uses the required
default channel unless the operator selects a configured logical destination.

## Create and configure the Slack app

1. Open [Slack apps](https://api.slack.com/apps), select **Create New App**, and
   choose **From scratch**.
2. Name the app `Nexgent` and select the intended workspace.
3. Open **OAuth & Permissions**. Under **Bot Token Scopes**, add only
   `chat:write` for this integration.
4. Select **Install to Workspace** and approve the installation. Reinstall the
   app after changing scopes.
5. Copy the **Bot User OAuth Token**, which begins with `xoxb-`. Store it only
   in the ignored `/agents/.env` file or the deployment secret manager.
6. In each destination channel, invite the bot:

   ```text
   /invite @Nexgent
   ```

   The integration deliberately does not request `chat:write.public`, so the
   bot must be a channel member.
7. Find the channel ID in Slack by opening the channel, selecting its name, and
   reading the ID at the bottom of **About**. Use the stable `C...` or `G...`
   ID, not a channel name.

Slack documents `chat:write`, channel membership, thread replies, Block Kit,
and per-channel posting limits in the official
[`chat.postMessage` reference](https://docs.slack.dev/reference/methods/chat.postmessage)
and [Python Web client guide](https://docs.slack.dev/tools/python-slack-sdk/web/).

## Environment

Required:

```env
SLACK_BOT_TOKEN=xoxb-your-token
SLACK_DEFAULT_CHANNEL_ID=C0123456789
```

Optional logical destinations and timeout:

```env
SLACK_CHANNEL_OPERATIONS=C0123456789
SLACK_CHANNEL_REPORTS=C0234567890
SLACK_CHANNEL_ALERTS=C0345678901
SLACK_REQUEST_TIMEOUT_SECONDS=10
```

Do not commit `.env`. The committed `.env.example` contains placeholders only.

## Reusable API

Default destination:

```python
from ax_integrations import SlackMessage, SlackService, SlackSettings

slack_service = SlackService(SlackSettings.from_env())
result = await slack_service.send_message(
    SlackMessage(text="Daily risk analysis has completed.")
)
```

Approved explicit channel:

```python
result = await slack_service.send_message(
    SlackMessage(
        channel_id="C0123456789",
        text="Three high-risk subscribers require review.",
    )
)
```

Logical destination:

```python
result = await slack_service.send_to(
    destination="alerts",
    text="A high-risk condition was detected.",
)
```

The explicit ID must already appear in configuration. Check `result.success`,
`result.message_ts`, and the sanitized `result.error`; do not treat delivery as
successful merely because no exception escaped.

## Send a transport smoke test

After adding the token and channel IDs to `/agents/.env`:

```bash
uv sync --dev
uv run --env-file .env ax-slack-send
```

Test the reports destination:

```bash
uv run --env-file .env ax-slack-send --destination reports \
  --text "Nexgent weekly report Slack delivery is ready."
```

The command prints only delivery status, channel ID, Slack timestamp, and a
sanitized error code. A successful response has `"success": true`.

## Generate and send a real weekly report

The manual sender needs the working Ansimk database, weekly-report source API,
and LLM configuration in addition to Slack. In terminal one, start the private
source API locally:

```bash
uv run --env-file .env uvicorn apps.weekly_report_api.main:app \
  --host 127.0.0.1 --port 8081
```

In terminal two, choose a Monday and preferably one reviewed ward for the first
test. The approval flag is mandatory:

```bash
WEEKLY_REPORT_SOURCE_URL=http://127.0.0.1:8081 \
uv run --env-file .env python -m workflows.weekly_report.slack_delivery \
  --week-start 2026-08-10 \
  --ward-id 1 \
  --approve-sensitive-delivery
```

Replace the date and ward ID with a period that has data. Review the configured
default channel and its membership before approval. Add `--destination reports`
only when `SLACK_CHANNEL_REPORTS` is configured and reviewed. The sender posts one
validated Markdown report per ward, spaces messages to respect Slack's
per-channel limit, and returns a delivery result for each ward.

## Tests

No automated test contacts Slack:

```bash
uv run pytest tests/unit/test_slack_integration.py \
  tests/unit/test_weekly_report_slack_delivery.py -q
```

The suite covers default and explicit destinations, text, threads, blocks,
missing configuration, rejected destinations, Slack API errors, rate limits,
timeouts, redaction, and weekly-report approval.
