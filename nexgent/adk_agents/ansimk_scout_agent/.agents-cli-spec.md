# Agent Spec

Date: 2026-08-27

## Overview

`ansimk_scout_agent` is a standalone Google ADK web-research backend POC. It
accepts a topic and optional keywords, lets one ADK Agent research through two
bounded Python Function Tools, and persists a validated Markdown report plus an
append-only JSONL execution log.

## Current architecture

- `ansimk_scout_agent`: the only ADK research `Agent`.
- `web_search`: bounded DDGS discovery Function Tool.
- `web_fetch_and_extract`: searched-URL-only HTTPX/Trafilatura evidence Function
  Tool.
- `ScoutRunService`: creates per-run tools, invokes the Agent once, validates the
  final report against successful fetches, and persists artifacts.
- No parent agent, sub-agent, deterministic planning Agent, SearchPlan stage,
  browser, scheduler, notifier, filesystem tool, or shell tool.

The existing internal `gemma-4-31b` OpenAI-compatible endpoint has now been
manually verified to support native tool calls. The earlier two-stage,
tool-free SearchPlan architecture was a temporary compatibility workaround and
is no longer the runtime architecture.

## Function-tool boundary

- The model formulates queries and chooses relevant returned URLs.
- Tools enforce three search calls, six unique search results total, and three
  fetch attempts per run.
- Fetch accepts only URLs returned by `web_search` in the same run.
- Search results are normalized, tracking parameters/fragments are removed, and
  URLs are deduplicated.
- HTTP(S), public-network, redirect, timeout, byte, content-type, and extracted
  character safeguards remain mandatory.
- Search snippets are discovery hints; only successful fetched text is evidence.
- ADK runs are capped at eight model calls.

## Report contract

The Agent returns Markdown with these ordered, non-empty sections:

```text
# Scout Report
## Topic
## Summary
## Key Findings
## Sources
```

Application validation requires at least one source and rejects every URL that
is not in the per-run successful-fetch set.

## API and artifacts

- `GET /health/live`
- `GET /health/ready`
- `POST /v1/scout/runs`

The POST request and success response remain backward-compatible. Artifacts are
confined to `<SCOUT_OUTPUT_ROOT>/runs/<uuid-hex>/{report.md,execution.jsonl}`.
User text never becomes a path.

## Constraints

- Configuration remains isolated to `OPENAI_API_BASE`, `OPENAI_API_KEY`,
  `SCOUT_MODEL`, and Scout-owned settings.
- No shared model configuration is imported or modified.
- No secrets, full prompts, raw model responses, or page bodies are logged.
- No Gemini, Vertex, or external model fallback is authorized.
- Frontend, scheduling, Slack, Docker, Compose, LangGraph, RAG, and Nexgent
  backend changes remain out of scope.

## Verification criteria

1. Offline tests validate single-Agent/function-tool registration, an actual
   controlled ADK tool-call loop, tool budgets, URL/fetch safety, successful URL
   tracking, report validation, atomic persistence, safe failures, and unchanged
   FastAPI contracts.
2. One bounded live request completes against the approved internal model and
   public web stack.
3. Live logs prove native `web_search` and `web_fetch_and_extract` calls occurred,
   and cited URLs are a subset of successful fetches.
