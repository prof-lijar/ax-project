# Agent Spec

Date: 2026-08-27

## Overview

`ansimk_scout_agent` is a standalone Google ADK web-research backend POC. It
accepts a topic and optional keywords, uses a tool-free ADK planning stage to
produce a validated SearchPlan, deterministically searches and extracts public
pages, uses a separate tool-free ADK summary stage, and persists a validated
Markdown report plus an append-only JSONL execution log.

## Architecture

- `search_planning_agent`: tool-free ADK `Agent` with `output_schema=SearchPlan`.
- `ansimk_scout_agent`: tool-free ADK summary `Agent` and public product identity.
- `ScoutRunService`: deterministic application orchestrator that invokes each
  stage explicitly and owns all web operations and persistence.
- No parent agent, sub-agent, native tool call, autonomous delegation, browser,
  scheduler, or notifier.

The shared `gemma-4-31b` endpoint currently rejects both `tool_choice="auto"`
and `tool_choice="required"` because its auto-tool-choice/tool-call-parser
support is not enabled. This project does not modify the server. Its working
flow is structured LLM planning, deterministic Python tools, then tool-free LLM
summarization.

## SearchPlan contract

```json
{"queries": ["one to three concise, URL-free search queries"]}
```

- One to three unique queries.
- Each query is normalized and limited to 160 characters.
- URLs and unknown schema fields are rejected.
- Application code validates the model output before DDGS is called.

## Deterministic web boundary

- `SearchProvider` remains replaceable; DDGS is the POC adapter.
- Total result budget is six, allocated across validated plan queries.
- Results are normalized, tracking parameters/fragments are removed, and URLs
  are deduplicated while preserving merged query/rank order.
- The first three unique eligible URLs are selected without an LLM or reranker.
- HTTPX owns fetches; Trafilatura is extraction-only.
- HTTP(S), public-network, redirect, timeout, byte, content-type, and extracted
  character safeguards remain mandatory.
- Individual fetch failures are recorded safely; summarization proceeds only if
  at least one page succeeded.

## Summary contract

The summary Agent receives only the original request and bounded successfully
fetched evidence blocks with their source URLs. Evidence is explicitly marked
as untrusted data, not instructions. The final response must contain:

```text
# Scout Report
## Topic
## Summary
## Key Findings
## Sources
```

Application validation requires non-empty sections and rejects any report URL
that is not among the successfully fetched URLs.

## API and artifacts

- `GET /health/live`
- `GET /health/ready`
- `POST /v1/scout/runs`

The POST request and success response remain backward-compatible with the first
POC. Artifacts remain confined to
`<SCOUT_OUTPUT_ROOT>/runs/<uuid-hex>/{report.md,execution.jsonl}`.

## Constraints

- Configuration is isolated to `OPENAI_API_BASE`, `OPENAI_API_KEY`,
  `SCOUT_MODEL`, and Scout-owned settings.
- No existing Nexgent shared model module is imported or modified.
- No secrets, full prompts, raw model responses, or page bodies are logged.
- No Gemini/Vertex/external model fallback is authorized.
- Frontend, scheduling, Slack, Docker, Compose, LangGraph, RAG, and shared
  backend changes remain out of scope.

## Verification criteria

1. Offline tests validate SearchPlan bounds, both tool-free Agents,
   deterministic DDGS invocation and URL selection, fetch safety, evidence
   isolation, source validation, artifacts, logs, failure layers, and API
   compatibility.
2. A single bounded live request completes against the approved internal model
   and public web stack.
3. The report cites only successfully fetched URLs and logs contain neither
   secrets nor raw page bodies.
